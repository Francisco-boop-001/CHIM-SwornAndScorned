# Written-evidence interface v1 (0.1.10)

S&S consumes neutral CHIM eventlog rows, never another plugin's private state. This interface is server-only; it does not accept browser/client prose or establish physical delivery. The producer must reject normalized client `info` with either reserved fifth-field marker (`written_evidence_v1` or `correspondence_v1`) before core logging and publish only after confirmed receipt and actual recipient-context/read exposure. A constant session marker is not cryptographic authentication against another privileged eventlog writer.

## Contract

`type=info`, `sess=written_evidence_v1` (logical input/source kind remains `written_evidence`), exact `people=|recipient canonical name|`. JSON has exactly `schema_version`, `document_id`, `playthrough_id`, `recipient`, `claimed_sender`, `body`, `receipt`, `attachments`. Version is integer1; scope is exact current CHIM profile id or `unprofiled`. NPC identities require unique canonical names and stable positive DB ids; Player requires current canonical name and null id. Only NPC recipients are supported perspectives. The claimed sender may be physically absent; neither that actor nor anyone else acquires knowledge by appearing in the metadata.

Document, receipt and operation ids are lowercase canonical UUIDs. Receipt is confirmed and exposure is `context` or `read`. Context exposure does not establish a reading animation or audible speech. Preserve nonempty original UTF-8 body (up to 2000 codepoints/8000 bytes). Ordinary speech remains capped at 640 codepoints per substance capsule. A written capsule receives the 2000-codepoint allowance only after its source envelope, exact body and claimed sender validate. New issue substance retains the complete origin of at most eight capsules and 5120 aggregate codepoints; oversized origins abstain from creation rather than truncate terms. Up to 8 confirmed received attachments have kind `gold|item`, unique stable `Plugin|8HEX` references and positive signed32-bit quantities. The gold reference is `Skyrim.esm|0000000F`. No actual hidden author/payer or operator provenance enters this record, model or logs.

## Public server API

Entry: `server/written_source.php`, namespace `ChimSwornAndScorned`. Use the plugin's `Pg` handle (the same checked CHIM connection used by its existing worker).

- `writtenEvidenceCapability(): array`: version1, input_type=`written_evidence`, source_event_type=`info`, source_marker, max_body_codepoints2000, max_substance_codepoints640, max_written_substance_codepoints2000, max_origin_codepoints5120, recipient_only=true. Capability is not proof the plugin is enabled or a source processed.
- `enqueueWrittenEvidence(Pg $pg, int $eventId): array`: accepts only a persisted event id; fetches and validates scope, identity, uniqueness and settings itself; requests the normal chronological scanner. It performs no model call or direct ledger write.
- `writtenEvidenceStatus(Pg $pg, int $eventId): array`: revalidates the source and distinguishes `invalid`, `paused`, `pending`, `queued`, `failed`, `abstained`, `processed`. A persisted `substance_budget` marker remains terminal and reports `abstained` on replay; it is not reopened. Queued/pending are not social success; processed means evaluation was committed, not necessarily that an issue was created or changed.

Queue/status read only enabled/use_jev/cast/model; they never load, decrypt or migrate saved keys. Pending/queued/paused results report `credential_readiness=unchecked`; the normal worker alone checks actual credentials.

The [sanitized verification record](verification/written-evidence-0.1.10.md) distinguishes deterministic interface checks from coordinator-run real-provider evidence. No HTTP endpoint or service is added. The normal worker remains responsible for transport retry/fallback and evaluation.

The existing structured logger emits `written_source_finished` for committed or replayed results and known terminal abstentions. It correlates by job, owner, playthrough and source event id and includes bounded origin event/codepoint counts; it never records names, letter text, prompts or keys. Fixed reasons include `written_source_invalid`, `written_source_changed`, `written_capacity` and `substance_budget`.

### Explicit worker wake (0.1.11)

Additional server-only entry: `server/written_worker.php`, namespace `ChimSwornAndScorned`, `wakeWrittenEvidenceWorker(Pg $pg): array`. This server-only entry is available in 0.1.11. Use the normal trusted CHIM runtime bootstrap (including `chimLoadGeneralSettingsIntoGlobals` and its database dependencies), then pass an idle checked CHIM connection. No caller-supplied settings, paths, PHP binary or document prose are accepted. Engine/plugin paths derive from the installed file; a development checkout is not a runnable CHIM installation.

The wrapper refreshes general settings, validates current playthrough availability and uses S&S's own settings loader and existing enabled/restore-policy/Jev-credential gates. It is CLI-only on Linux and runs the fixed installed `worker.php --settle-once` in a fresh child under `/usr/bin/timeout --signal=KILL 60s /usr/bin/php`. The existing worker's normal lock still prevents competing ticks. No lasting daemon is launched. Supported CHIM core holds a shared save/restore runtime lease for the process lifetime, so this bounded process also bounds that lease. Separately, the ordinary 0.1.11 daemon cooperates with core pause by stopping evaluation between passes/before commit and exiting to release its lease.

The new mode polls the existing scanner once a second for at most 21 seconds of idle waiting, allowing its normal 20-second quiet interval to elapse without another dialogue or mail event. It exits after the first attempted job (including a failed/retryable model result), disable/pause, interaction change, idle deadline or error; it neither retries model failures in a loop nor seeds lore. Ordinary `--once` and daemon modes do not acquire this quiet-waiting loop. The daemon also retains its normal settings pause/resume behavior and now yields to CHIM playthrough switching. An older eligible job may consume this one attempt.

The child captures CHIM's interaction generation once before polling. Its settings carry that same witness through `PgJobDeps` to the store, which rechecks enabled state and exact generation immediately before writing. A nonblocking shared lock on the core interaction file remains held through ledger/affinity UPDATE, history and COMMIT; the actual core toggle takes the corresponding exclusive lock. Off/On during evaluation therefore rejects the write as `interaction_changed`. Missing core APIs or unreadable, malformed or contended state fail closed; a fresh empty state follows core's default of enabled at generation0. Existing callers without this optional new-mode witness preserve their behavior; this is not a retrofit of ordinary daemon interaction safety.

Only this mode's supported relationship-LLM helper uses its inner 20-second GNU timeout with `--foreground`, keeping that helper in the outer worker's timeout process group. The outer timeout retains its normal group behavior. Arbitrary descendants that deliberately create another process group can still escape it; no universal descendant-cleanup guarantee is made. Quiet waiting plus two worst-case 20-second REL requests and bootstrap can exhaust the outer 60-second budget; timeout is an unsuccessful wake, not evidence of processing or settlement.

A missing normal bootstrap, invalid installed layout, active caller transaction, unavailable bounded runner or error fails closed. The caller synchronously reaps the bounded child; child stdout/stderr are discarded. It does not run raw evaluator work in the caller, modify lifecycle rules or create a new service. Unlike queue/status reads, this explicit command loads private settings and may perform their existing legacy-key encryption migration. Secrets and exception text never enter its return value. Run it within a separately bounded, freshly bootstrapped CLI helper: setup queries and the caller's own core lease remain the helper owner's responsibility.

Returned `status` and fixed `reason` values:

- `paused`: `playthrough_unavailable`, `disabled`, `restore_policy`, `key_storage_unavailable`, or `jev_credentials_unavailable`.
- `unavailable`: `engine_unavailable`, `settings_bootstrap_unavailable`, `transaction_active`, `tick_unavailable`, `spawn_failed`, `tick_timeout`, `tick_failed`, or `wake_failed`.
- `running` / `existing_worker`: the PID check observed a matching existing daemon. This is only an observation: the wrapper does not stop it or repair its already-held runtime lease.
- `tick_finished` / `child_exited`: the bounded child exited zero. It can mean another worker held the lock, eligibility/interaction changed, the idle deadline expired without a job, or one job was attempted. It never means a specified source was processed.

Producer sequence: persist actual recipient exposure → call `enqueueWrittenEvidence` outside a transaction → optionally request a bounded tick → bounded `writtenEvidenceStatus` readback. The scanner can wait for settlement and process older eligible work first. None of pending, queued, running or tick_finished means a social effect occurred; even processed can mean evaluation committed with no issue change. A timeout/failure may interrupt already-started work, so reconcile source state before a retry; existing job leases/replay govern recovery. No automatic restart loop is added here. All-written new promises remain unsupported without the existing actual owner-speech evidence.

The deterministic `tests/written_worker_test.php` copies the exact wrapper into an isolated layout and scripts only its process/DB boundary. It rejects daemon launch and checks the fixed one-tick argv/deadline, synchronous reap, timeout/nonzero outcomes, eligibility gates and secret exclusion. This alone is not runtime proof.

Controlled disposable integration separately exercised the actual supported foreground relationship-LLM helper, worker/controller/helper process identities and group, core restore lease and bounded timeout cleanup. The deliberately escaping-process-group failure remains outside the guarantee; arbitrary descendants can escape a process group. Cooperative core switching was checked independently for the ordinary daemon. These controlled fixtures do not establish real-provider latency, arbitrary SQL-stall cleanup, native Skyrim behavior or safe handling of an arbitrary whole-shell kill. ## Interpretation, persistence and restore

The body is what the letter claims; received attachments establish quantities reaching the recipient, not the signature's authorship, who paid, acceptance of a new obligation or satisfaction of a particular debt. Both typed evaluators see modality and claimed attribution, never synthetic spoken dialogue. Written attribution must be supported before blaming the claimed sender. One-sided letters cannot manufacture recipient acceptance. A letter's claim alone cannot fulfil money/item debts or resolve/forgive the recipient's grievance. Ordinary actual recipient acknowledgement can support later settlement through existing speech rules.

Exact written provenance follows source capsules and evidence through normalization, history, later questions, journal and bounded reminder. Existing records remain readable and ordinary acknowledged speech filtering stays unchanged. Only `PerspectiveStore::commitLedger` writes ledger/history/affinity. It locks/revalidates current scope, cast/identities, exact source and envelope, checks alternate document/recipient or receipt/operation rows, and refuses missing/tampered sources. Source kinds retain separate replay identity.

Written source identities live in the restored owner ledger/history. Never evict them: at1024 retained sources, abstain with `written_capacity` until a separately designed storage extension exists. This bounds restored snapshots without silently permitting replay. The interface adds no automatic historical cleanup, independent affinity policy or provider service.

## Carrier privacy amendment

The custom physical type `written_evidence` is rejected: inspected generic/Narrator/BGL history readers can accept unknown types, and compaction can discard the original type before late hooks. Only core-excluded physical `info` plus exact `written_evidence_v1` is accepted; there is no legacy fallback. The producer must block reserved client markers before the core logger copies request field4 into sess. S&S itself does not patch core. A compatible producer/platform must actually exclude this carrier from general history and reject reserved client markers before logging; installing S&S does not establish those producer/core safeguards.

S&S scanners and bootstrap queries select speech or exact-marker info, so unrelated plaintext info and private correspondence_v1 anchors neither enter the evaluator nor consume its scan budget. Collision SQL uses an explicit MATERIALIZED marker-restricted CTE before JSON casts. Current source rows remain locked/revalidated by the existing store; no general info-history scan or new ledger format is introduced. Completed disposable checks cover scanner-budget exclusion with more than 500 unrelated ordinary/private-anchor info rows, pre-cast marker isolation, carrier/marker mutation during evaluation, rejection of the unsafe raw type, locked source validation and the existing substance/affinity/replay invariants. The sanitized verification record describes the completed cross-product and installer scope; no native-game result is inferred.

## Labelled forwarded copies

A forwarded copy remains ordinary exact v1 body text. The shared evaluator state distinguishes current cover words from quoted prior claims; copy labels do not authenticate segment authorship, create a new receipt, or make an old promise, insult, refusal, release or payment a current declaration by the forwarding sender. An explicit present endorsement must be judged separately. Unknown attribution abstains. No quote-stripping, hidden lineage fields, new backend service, acceptance rule or affinity policy is introduced.

The focused quote regression checks exact body/identity preservation, the same question/state reaching both typed adapters, genuine current promise/acceptance, false or missing attribution gates, and unsupported written-settlement no-effects. A rejected terminal claim skips its complete update, preserving issue trajectory, evidence and freshness as well as status/affinity. Genuine no-change discussion can still retain addressed evidence. Actual real-provider cases are reported separately in the [verification record](verification/written-evidence-0.1.10.md).
