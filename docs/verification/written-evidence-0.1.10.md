# Written evidence and attribution: 0.1.10 verification

0.1.10 is PRE-ALPHA. Its runtime matches the independently accepted 0.1.9-autonomy.dev.3 candidate except for the release manifest version. Publication packaging is verified separately; neither publication nor downloading installs it on a running server.

## What changed

A compatible trusted server producer can expose a persisted, recipient-only written-evidence record through the documented v1 interface. S&S uses its ordinary scanner, worker, typed evaluator, locked PerspectiveStore, history and affinity path. Immutable source identity and exact body/envelope persist through later questions, journal and bounded reminder. Legacy records remain readable; no historical terms, grievances or affinity are automatically rewritten.

The shared model guidance separates a current statement/endorsement from enclosed old claims. The attribution question now explicitly covers current unquoted words while retaining disputed/unclear attribution safeguards. A letter alone cannot establish recipient acceptance, payment or forgiveness. Rejected written terminal claims skip their whole update, so they cannot leak an improving trajectory, addressed evidence or freshness. Genuine discussion remains recordable.

## Boundaries and remaining risks

- This release supplies a server evidence interface. It does not itself send letters or provide spontaneous fully offscreen NPC correspondence. Compatible producers have their own installation/core requirements.
- Current correspondence support is bounded/reactive. Generated NPC letters have no attachments; autonomous gifts, trades, loan repayment and a complete forgery-discovery/accountability system are not implemented by this release.
- Receipt confirms this source's exposure/listed attachments, not authorship, a hidden payer, inventory accounting or settlement of a particular debt. Labels and signatures are not authenticated quote segments.
- Complete new-record origin remains bounded to eight utterances of 640 characters. The restored ledger retains at most 1024 written source identities without eviction, then abstains on further written evidence. Cross-batch acceptance, large-history throughput and broad concurrency remain limited/unverified.
- The conversation reminder remains 240 characters and may omit details present in the journal/evaluator context.
- Back up the server before upgrading. Returning to older code requires its matching ledger/history snapshot because older readers do not understand written provenance metadata. This is not a promise of automatic downgrade migration.
- No live installation, Skyrim gameplay, physical delivery/reading animation, audible dialogue or long-session reliability is certified. The disposable fixtures were restored and stopped; the gaming distro was not entered. No API calls or server start are needed for publication.
