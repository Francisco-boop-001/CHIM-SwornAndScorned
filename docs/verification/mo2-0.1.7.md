# MO2 packaging correction — 0.1.7

This release changes packaging and installation instructions. The runtime manifest version is 0.1.7; the other 38 runtime files remain byte-identical to published 0.1.6. Publication does not install it on the gaming server.

## Executed checks

- A new package regression first failed because the MO2 ZIP lacked `meta.ini`. All three package tests then passed: exact server payload/checksums, output-path protection, and MO2 metadata plus reproducible release assets. Two independent builds produced identical DWPkg, tar, MO2 ZIP and checksum bytes.
- The MO2 ZIP contains only root `meta.ini` and `CHIM/server-plugins/sworn_and_scorned/0.1.7.dwpkg`. Version comes from the runtime manifest; metadata includes a public project URL and `validated=true`. No Nexus ID, account tracking flags, private settings or machine paths are shipped. Metadata stays outside both the DWPkg and tar server payloads. The embedded DWPkg is byte-identical to the standalone file; ZIP CRCs pass.
- On the registered disposable CHIM clone, byte-identical copies of core's package manager and HTTP endpoint ran under `www-data` in a temporary server root. The real probe/start-upload/three-chunk/status/list protocol accepted the MO2-embedded DWPkg, activated all 39 files matching final source, reported 0.1.7 and correctly skipped a repeat-version probe. No transport or importer stubs were used.
- Negative HTTP checks rejected a tar filename and rejected the outer MO2 ZIP as a server package; the previous successful installation and its version ledger survived both failures.
- Core's original files and the clone's original extension were unchanged. The temporary HTTP process and scratch root were removed. These checks used no database, model provider or gaming-server services.
- Published 0.1.6 assets were retained unchanged.

## Source contracts and documentation corrections

[MO2 2.5.2 reads the version, custom URL and validated flag](https://github.com/ModOrganizer2/modorganizer/blob/v2.5.2/src/modinforegular.cpp). The validated flag suppresses the installed mod's missing-content indicator. It is not a declaration that the initial install dialog recognizes CHIM's custom directory, nor that a server upload succeeded. [MO2's installer can rewrite manager-owned metadata](https://github.com/ModOrganizer2/modorganizer/blob/v2.5.2/src/installationmanager.cpp); this release does not promise GitHub update polling.

The inspected CHIM Plugin Manager says bundled packages synchronize when a save is loaded and has no manual-upload control. Its status message “Could not read automatic package status” comes from reading the package-status API; it does not identify a malformed archive by itself. The README now recommends one MO2 download, explains the launch/load trigger and installed-version completion check, and distinguishes server errors from MO2 content warnings. Standalone assets are identified as formats for supported admin/installer tooling rather than additional MO2 requirements. The [CHIM modders guide](https://raw.githubusercontent.com/Dwemer-Dynamics/DwemerDynamics/main/chim/modders-guide.html) documents the game-carried package layout and separate catalog/tar route.
