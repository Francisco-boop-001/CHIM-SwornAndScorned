# Tone interpretation — local 0.1.8 candidate

The shared evaluator questions now distinguish genuine personal harm from affectionate insults, consensual positive intensity, mock outrage and competitive combat banter. Ambiguous insults alone do not establish a grievance. Affectionate vocabulary or smiling does not override an explicit genuine complaint. A remedy is not invented from swear words alone.

Existing-issue questions match the original harm or obligation. Unrelated gifts, generic apologies and shared names do not settle a matter. Explicit acknowledgement that the specific wrong was repaired or the promised action completed remains valid evidence. Evidence selection prefers the owner’s explicit acknowledgement, then the latest equally direct line, avoiding probability splits between interchangeable lines.

## Verification

The registered disposable clone was isolated to a Unix-socket-only PostgreSQL instance. No gaming-distro connection or live modification was made.

Before the correction, real Jev evaluation failed four of fourteen synthetic cases: combat rivalry and an ambiguous insult became grievances, and two clear settlement/fulfilment cases could not pass evidence-line confidence. The latter selected the correct status but split probability between two valid source lines. Thresholds were not lowered.

After correction, all fourteen cases passed three real Jev runs (42 case evaluations) and one real CHIM relationship-LLM run (14 case evaluations). The corpus covers affectionate insults/intensity, combat score/rivalry, ambiguous intent, theft, genuine hurt despite affectionate language or a smile, abandonment, banter beside an existing theft grievance, specific restitution, unrelated gifts, and explicit fulfilled/broken promises. These are synthetic model observations, not a general accuracy guarantee or gameplay proof. Real API calls incur charges.

All 33 regular PHP scripts passed: 32 ran under the clone’s database user, and the root-only provisioning fixture passed separately under root. Store, queue and Jev-selection database integration suites passed in the disposable `sas_it` schema. The real-model test is opt-in (`SAS_MODEL_TEST=1`) and refuses any other distro or a TCP-listening test database. It emits only synthetic case IDs, typed decision metadata, outcomes and timings; credentials and raw provider bodies are not printed.

## Limits

This is a prompt-semantic correction using the existing protocol, validation, confidence thresholds and ledger schema. It adds no model round trip or keyword blacklist. Existing recorded mistakes are not deleted or reclassified, and historical affinity is not rewritten. No live upgrade or publication is included.

The ledger still relies on originating/latest evidence plus kind, direction, status and requested remedy. An explicit evidence-backed description of the wrong or obligation and its settlement conditions is a separate proposed change. The user chose to review that design after the tone fix; it is not implemented here. Unstated feelings, ambiguous intent and unobserved game actions remain uncertain.
